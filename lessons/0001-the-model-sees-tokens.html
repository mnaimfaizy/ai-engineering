The model does not see words

Your first engineering skill: look at a chat and see a sequence of token IDs, not English. Every later pattern — context, tools, skills, loops, graphs — is a way of spending that sequence on purpose.

The trick ChatGPT hides

When you type a sentence, it feels like the assistant “reads” it. Under the hood the pipeline is mechanical — and this skeleton is shared by GPT, Claude, Llama, Gemini, and the rest:

Watch the highlight move: every chat turn is this loop. The flavour is which tokenizer sits in step 2.

Karpathy’s one-line picture: the network is a next-token predictor. Chat products are that predictor, wrapped in a loop, with extra training so it answers as an assistant rather than continuing a webpage. Intro to Large Language Models, first third of the talk.

OpenAI: tokens “can be as short as a single character or as long as a full word.” Billing and context limits are token counts, not word counts. What are tokens and how to count them?

Tokens are a learned alphabet

If we gave the model one ID per Unicode character, sequences would be long and expensive. If we gave it one ID per English word, it would choke on typos, code, and other languages. The compromise used by GPT-style models is byte-pair encoding (BPE): start from bytes, repeatedly merge the most common adjacent pairs into a new vocabulary entry. Frequent chunks (“the”, “ing”, a leading space plus a common word) become single tokens. Rare strings stay split.

Two consequences you will keep meeting:

  • Case and spaces are real. Hello, hello, and hello are often different IDs.
  • Odd failures are sometimes tokenizer failures. Arithmetic, Unicode, and “the model can’t see that space” bugs often start here — Karpathy calls tokenization gnarly for exactly this reason. LLM Tokenization lecture notes

Same skeleton, different flavour

The dropdown changing the split is not a bug. The job is the same for every modern LLM: map text to a sequence of integer IDs from a fixed vocabulary, then predict the next ID. Hugging Face groups the algorithms as three subword cousins — BPE, WordPiece, and Unigram — plus SentencePiece as a library that can run BPE or Unigram on raw text (spaces included). Tokenization algorithms

The dictionary is not shared. Each model family trains its own vocabulary on its own data, with its own size and merge rules. Token ID 1234 is a different chunk in GPT-4 than in Llama. OpenAI says this outright: “Different models use different encodings,” and ships several (r50k_base, p50k_base, cl100k_base, o200k_base). Their cookbook even compares the same English word across encodings and gets different splits. How to count tokens with tiktoken

Shared

Text → tokenizer → IDs → next-token loop. Subword chunks, not whole words.

Per family

Vocabulary, merge table, special tokens, even how spaces are stored. Count with that model’s tokenizer.

It changes inside a vendor too. Llama 2 used SentencePiece; Llama 3 switched to a tiktoken-style BPE. Anthropic documents that Claude 4.7 and later use a newer tokenizer: the same input is about 30% more tokens than on earlier Claude models — so you recount against the model you will actually call. Engineering rule for later (RAG, agents, cost caps): count tokens with the tokenizer that belongs to the model you will run. A GPT encoding will mis-budget a Claude or Llama prompt.

Why this is lesson one for an AI engineer

This course ends at harnesses, skills, plugins, context engineering, loop engineering, and graph engineering. Those names all sit on one fact:

Context is a finite attention budget, measured in tokens. The job is the smallest set of high-signal tokens that make the next action likely. Anthropic, Effective context engineering

A tool dump, a retrieved PDF, a SKILL.md, a looping agent’s history — each is more tokens in the same window. If you cannot see the window, you cannot choose an architecture. That is the whole course in miniature: judgment starts with the budget.
